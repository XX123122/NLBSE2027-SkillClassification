# Fixed-role commands and explicit execution boundaries

All commands below are for a **later authorized local Linux execution**, not for
this packaging task. All real stages require `--execute`; the default is a plan.
Use separate CPU/GPU environments and a new absolute `WORK_DIR` outside the source
repository. Nothing is sent to a remote queue. Training runs in the foreground.

```sh
export PYTHONPATH="$PWD/src:$PWD/scripts"
export SKILLCOMP_ENCODER_PYTHON=/absolute/path/to/encoder-env/bin/python
WORK_DIR=/absolute/path/to/new-role-work
DB=/absolute/path/to/skillscope_data.db
```

Copy the asset-map example to the project root and configure actual asset paths.
`--stage prepare` requires the exact pinned SQLite hash and refuses an existing
work directory. It copies source/config into the new work directory, symlinks the
declared read-only database, binds CodeBERT and Qwen paths, regenerates data roots,
derives the specified historical role and fits lexical vocabularies on its fit rows.

```sh
python scripts/reproduce.py --role fold0_inner0 --stage prepare --execute \
  --work-dir "$WORK_DIR" --database "$DB" --asset-map asset-map.json
```

Execute the following stages sequentially with the same role, database, work
directory and encoder interpreter. For each command substitute one `STAGE`:

| Stage | Environment | Inputs produced earlier | Outputs |
|---|---|---|---|
| `tokenize` | encoder, CPU tokenizer | regenerated text and role configs | fresh token arrays |
| `encoder-fit` | encoder, CUDA | tokens, observed fit proxy targets | fixed 2/4/8 epoch checkpoints |
| `base-encode` | encoder, CUDA | regenerated original text | Qwen0.6 original-whitespace vectors |
| `extract` | encoder, CUDA | fresh 8-epoch checkpoint | supervised vectors |
| `base-fit` | CPU | lexical and original-whitespace vectors | fixed C1 original base branch |
| `normalized-encode` | encoder, CUDA | regenerated original text | Qwen0.6 normalized-whitespace vectors |
| `experts-fit` | CPU | fresh supervised vectors plus declared input-only Qwen4 cache | trees, NN, availability/conditional maps |
| `active-base-fit` | CPU | normalized base features and fresh experts | fixed selected fold0_inner0 continuous scores |

```sh
# Select and reserve an allowed GPU on the local host before GPU stages.
# CPU/tokenization stages do not require --gpu.
python scripts/reproduce.py --role fold0_inner0 --stage STAGE --execute \
  --work-dir "$WORK_DIR" --database "$DB" --asset-map asset-map.json \
  --encoder-python "$SKILLCOMP_ENCODER_PYTHON" --gpu GPU_INDEX
```

`GPU_INDEX` and `STAGE` are explicit user-supplied arguments, not defaults. The
runner requires a GPU number for CUDA stages; it does not acquire a multi-user
training reservation or silently choose a device. The separate inference CLI does
have its shared registry reservation helper. The historical hardware exclusions
have been removed from copied source and are site-configurable.

`experts-fit` additionally requires `--frozen-qwen4-features /absolute/path/to/input_only.npy`
and `--frozen-qwen4-sha256 EXPECTED_HASH`. That cache is **not distributed** and must
be regenerated by a declared input-only Qwen4 transform or explicitly supplied
with trusted text identity/hash provenance. A matching file hash alone does not
prove that arbitrary supplied features are label-free. The historical successful
continuation verified both content hash and original text identity; the new runner
only verifies the declared hash, so this input provenance remains a manual release
gate in the machine-readable gap list.

The base-role adapter derives all development roles, but only `fold0_inner0` has
historical numerical rebuild evidence. The other adapters have synthetic role
tests only. Active-policy execution for other roles fails closed because their
retained reference choices differ. Full-data roles support planning and preparation;
encoder training is blocked until exact four-epoch scheduler semantics are resolved.

No tuning or final score is computed by this bounded role sequence. To inspect the
historical tuning/evaluation/export scope safely:

```sh
python scripts/reproduce.py --role fold0_inner0 --phase tune
python scripts/reproduce.py --role fold0_inner0 --phase evaluate
python scripts/reproduce.py --role full_final --phase export
python scripts/check_saved_results.py
```

The first three print blockers; `--execute` rejects them. The last checks saved
aggregate consistency only. Historical entrypoints included for source review are
`run_conditional_peer_union_capability.py`, `select_full_conditional_peer_union.py`,
`select_full_tree_conditional_union.py` and `export_full_conditional_tree_candidate.py`.
Their historical cache paths, prerequisite fitted outputs and selection metadata
are unresolved by a full portable producer graph. Do not copy historical fitted
caches into a fresh directory and call it a clean rebuild.
